# DynastyLink Bubble App Blueprint

## Purpose
DynastyLink is the onboarding application for AI Freedom Trust Federation. It helps a person create a sovereign trust identity, understand the federation covenant, complete guided intake, receive AI-guided education, and prepare to become a Federated Trust within the broader 1000-year dynasty trust vision.

## Legal-Safe Position
DynastyLink is an educational, organizational, and record-preparation platform. It does not provide legal, tax, investment, insurance, or financial advice. Any trust documents, financial plans, or legal structures generated by the app must be reviewed by qualified professionals before use.

## Core Product Promise
Discover -> Discern -> Declare -> Document -> Federate -> Govern -> Grow.

## Bubble Data Types
### User
Fields: email, full_name, role, phone, verified_identity, onboarding_stage, trust_profile, privacy_consent_date, terms_version.

### Trust_Profile
Fields: trust_name, owner_user, status, mission_statement, family_legacy_statement, beneficiary_vision, jurisdiction_state, advisor_assigned, covenant_signed, federation_id, public_slug.

### Readiness_Assessment
Fields: user, answers, score, recommended_path, ai_summary, created_date.

### Covenant_Agreement
Fields: user, trust_profile, covenant_version, accepted, accepted_date, signature_text.

### Document
Fields: owner_user, trust_profile, file, doc_type, visibility, review_status, notes.

### AI_Conversation
Fields: user, trust_profile, messages, response_tracking_id, topic, risk_level, created_date.

### Advisor_Review
Fields: trust_profile, advisor_user, request_type, status, notes, required_documents, completed_date.

### Federation_Membership
Fields: user, trust_profile, federation_id, membership_status, start_date, contribution_plan, governance_weight_placeholder.

### Payment_or_Contribution
Fields: user, trust_profile, amount, type, payment_provider_id, status.

### Content_Module
Fields: title, category, body, video_or_file, order, required_for_stage.

### Audit_Log
Fields: user, action, object_type, object_id, timestamp, metadata.

## Core Workflows
1. Sign up: create User, set role to Applicant, create blank Trust_Profile, redirect to dashboard.
2. Complete readiness quiz: calculate score, call AI summary workflow, save Readiness_Assessment.
3. Build trust identity: validate fields, update Trust_Profile, write Audit_Log.
4. Accept covenant: create Covenant_Agreement, lock covenant version, advance onboarding stage.
5. Upload document: create Document, set visibility, notify admin if required.
6. Ask AI Trust Guide: call backend API workflow, save AI_Conversation, return educational answer with disclaimer.
7. Submit for review: verify required data, update status, notify admin.
8. Admin approval: update status to Approved or Federated, create Federation_Membership, send welcome email.
9. Advisor review: create Advisor_Review, assign professional, notify user.
10. Contribution/payment: complete provider checkout, update Payment_or_Contribution, unlock applicable member features.

## Privacy Rules
- Users view only their own private records.
- Admins view applicant/member records required for operations.
- Advisors view only assigned profiles and documents.
- Public pages expose no private data.
- API keys must never be client-side.
- OpenAI calls should run server-side through Bubble backend workflows/API Connector.
- Every sensitive data type must have Bubble privacy rules before launch.
